# v0.2.2：真实扫描PDF取图回归

## 真实故障

用户在DSH桌面版调用 `gwz_page_prepare(page=40, detail=image, mode=auto, dpi=150)` 后，收到 `INVALID_TOOL_OUTPUT: value is not lossless JSON`。远端任务实际已完成，原图预览已经下载。

出错值位于 `result.image_to_pdf_transform[2]`，是Python输出的 `-0.0`。这是合法的JSON数值；JavaScript JSON.parse保留其负号，而DSH无损JSON边界会拒绝负零。普通JSON.stringify会把它写成0，原先模拟器恰好掩盖了这个真实返回形式。

## 修复与确定性验证

- 在CLI解析与公共工具返回边界将数值负零规范成零。几何意义不变，原始响应字节完整留在日志；不改模式、DPI或源图，不丢弃原有信息。
- 其他无法无损传输的数据显式指出字段路径，不用JSON.stringify悄悄删除undefined或把非有限数值变成null。
- 先加入能保留Python负零的模拟器，确认旧代码稳定失败；再修复，确认同一测试通过。
- 用实际DSH工具服务验证原值拒绝、规范值通过；对41×41网格点验证变换几何结果不变。
- 枚举嵌套标量组合，检查规范化幂等性、JSON往返、原值未被修改，并检查循环、稀疏数组、非有限数值等错误路径。

## 真实DeepSeek／官方DSH／远端服务

为避免打断用户会话，使用单独的DSH_HOME、工作文件夹和官方DSH 0.2.1-rc.5 headless入口。不是自制模型循环或替换后的工具执行器：使用官方Agent、DeepSeek API适配器、本地子进程与附件服务，以及真实guwenzi-tools账号与远端服务。

测试模型为用户当前使用的 `deepseek-flash`，本次隔离测试关闭思考，不改变用户生产设置。只让模型取已登记PDF的物理第40页、原参数调用一次，然后确认收到图像；不上传新文档、不OCR、不检索/造字、不扫描全书。API密钥仅通过父进程内存注入启动环境，不进入命令参数、提示词、仓库或日志；关闭该测试实例的遥测与额外标题模型调用。

补齐原图来源字段后的第二轮完整回归也通过：工具调用开始8.079秒、完成11.496秒，工具阶段约3.417秒，整轮进程16.635秒正常退出。仍只有一次指定参数的page_prepare，无重试。模型这次明确区分了内嵌原图与按DPI重渲染。最终代码的22项本地测试全部通过，0失败、0跳过，包含真实LaTeX编译与独立Python环境分支。

同时发现模型可能把 `route=raster`误说成“按DPI渲染”。现在将 `source_image_original`、`render_kind`、`pixel_resampling`和变换矩阵纳入紧凑返回，并在工具说明里明确：`pdf_embedded_original`表示直接提取内嵌原图，不能只凭route字段推断重采样。
